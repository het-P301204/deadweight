# Fixtures

## `demo-project/`

A fabricated service, `atlas-triage`. Nothing in it is real: no real weights,
no real credentials, no real endpoints, no real customer. It is the project
the web app's demo mode analyses and the project the CLI is tested against —
the same files, through the same engine, which is the only reason the demo is
worth anything as a demonstration.

`src/demo-tree.generated.ts` is compiled from this directory by
`npm run demo-tree`, and CI checks that it still matches, so the two cannot
drift.

### The binary artifacts

`weights/*` and `models/*` are generated by `scripts/make-fixtures.ts`. They
are not models. Each is the smallest byte sequence that is genuinely
recognisable as its format: a real pickle opcode stream, a real zip central
directory, a real length-prefixed safetensors header. The analyser has to
identify them from their bytes, so they have to be real bytes.

Regenerate with `npm run fixtures`; verify with `node scripts/make-fixtures.ts
--check`, which CI runs.

### `weights/classifier.pkl`

Contains a pickle stream that names `os.system` and carries a `REDUCE`
opcode. A detection fixture for a pickle scanner has to contain the thing
being detected, which is why every pickle-scanning tool keeps something like
it in its test corpus.

**It is inert.** A pickle is data until something unpickles it. DEADWEIGHT
never unpickles anything — it walks opcodes and constructs nothing — and
nothing in this repository, in CI, or in the browser build passes this file to
an unpickler. Its argument string is `echo DEADWEIGHT SYNTHETIC FIXTURE`.

## `malformed/`

Inputs the analyser has to refuse, or survive, without throwing. Each one is
also documentation of a failure mode: what a hostile or broken file looks like
and what DEADWEIGHT does about it.

The engine test suite walks this directory and asserts that every file
produces a report rather than an exception, and that nothing in the resulting
document contains a control character.
